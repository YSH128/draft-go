## 1. 페이즈 개요

1. **로비(Lobby):** 참여자 모집, 역할/포지션 배정 및 준비 단계
2. **드래프트(Draft):** 실시간 경매를 통한 팀 구성 단계
3. **결과(Result):** 최종 팀 구성 확인 및 히스토리 저장 단계

---

## 2. 역할별 상세 여정

### [관리자: 운영 및 중재자]

관리자는 경기 운영의 전권을 가지며, 필요 시 직접 선수(팀장/팀원)로 참여할 수 있습니다.

| **단계** | **주요 시나리오** | **상세 액션** |
| --- | --- | --- |
| **로비** | **대회 생성 및 관리** | - 대회 이름, 팀 수 설정 후 방 생성
- 초대 코드(팀장용/팀원용) 생성 및 배포
- 참여자 권한 변경(팀원↔팀장) 및 강제 퇴장(Kick)
- 참여자 포지션 강제 조정 및 팀장 포인트 조정 |
  | **드래프트** | **세션 제어 및 관전** | - 모든 팀장 준비 완료 시 드래프트 시작 버튼 활성화
- 경매 진행 상황 실시간 모달/채팅 모니터링
- 관전용 외부 공유 링크 생성 |
  | **결과** | **최종 승인** | - 드래프트 결과 확인 및 세션 종료 |

---

### [팀장: 전략적 구매자]

팀장은 부여된 포인트를 사용하여 팀을 구성하는 핵심 주체입니다.

- **포인트 지급 원칙:** 본인의 티어가 높을수록 낮은 시작 포인트를 배정받습니다. ()
- **구매 제한:** 본인 포지션 제외 4개 포지션 구매 가능 (포지션당 1명).

| **단계** | **주요 시나리오** | **상세 액션** |
| --- | --- | --- |
| **로비** | **전략 수립** | - 초대 코드로 입장 후 본인 포지션 선택
- 참여자 풀(티어, 주포지션, 모스트 챔피언) 분석
- **준비 완료(Ready)** 상태 전환 (모든 팀장 완료 시 시작 가능) |
  | **드래프트** | **경매 참여** | - 순차적으로 등장하는 선수에 대해 입찰(Bidding)
- 실시간 잔여 포인트 및 타 팀 구성 현황 파악
- 유찰 선수 발생 시 '재입찰 드래프트' 참여 |
  | **결과** | **로스터 확인** | - 완성된 팀 로스터 확인 및 마이페이지 저장 |

---

### [팀원 및 관전자: 피선택자 및 시청자]

팀원은 드래프트의 대상이며, 관전자는 채팅을 통해 소통합니다.

| **단계** | **주요 시나리오** | **상세 액션** |
| --- | --- | --- |
| **로비** | **참가 신청** | - 코드로 입장 후 희망 포지션 설정
- 참여자 명단에서 본인의 정보가 올바른지 확인 |
| **드래프트** | **실시간 관전** | - 본인이 어느 팀에 낙찰되는지 실시간 확인
- 채팅을 통해 팀장들과 소통 및 반응 송출 |
| **결과** | **소속 팀 확인** | - 확정된 소속 팀원들과의 결과 페이지 공유 |

## 3. 핵심 비즈니스 로직 (Edge Case 처리)

### A. 유찰 선수 처리 프로세스 (Draft 종료 직후)

정규 드래프트에서 선택받지 못한 선수가 있을 경우 아래 로직을 따릅니다.

1. **재입찰:** 포지션이 비어있는 팀장들 간에 남은 포인트로 재경매 진행.
2. **강제 배정(Random Fill):** 포인트가 0인 팀이 다수일 경우 시스템이 랜덤 배정. (???)
    - **보정 로직:** 상대적으로 티어 합이 낮은(약세) 팀에 더 높은 티어의 유찰 선수가 배정되도록 우선권 부여.

### B. 상태 동기화 (Socket 연결)

브라우저 종료나 네트워크 불안정 대응을 위해 아래 기능을 포함합니다.

- **Heartbeat:** 소켓의 Ping/Pong을 통해 사용자의 접속 상태(Online/Offline)를 UI에 표시.
- **Broadcast:** 관리자의 권한 변경, 팀장의 준비 완료, 입찰 상황 등을 모든 접속자에게 실시간 전파.
