# Day 3: Stitch & Figma 연동 학습 (2026-01-15)

## 1. Stitch란?

### Stitch 개요

- **AI 기반 UI 생성 도구**로, 자연어 프롬프트를 통해 화면을 자동으로 생성
- Figma와 연동하여 디자인 워크플로우를 간소화
- 디자이너와 개발자 간의 협업 효율성 향상

### 주요 특징

- **AI 프롬프트 기반 디자인**: 텍스트 설명만으로 UI 화면 생성
- **Figma 플러그인 지원**: Stitch에서 생성한 디자인을 Figma로 가져오기
- **빠른 프로토타이핑**: 아이디어를 신속하게 시각화

---

## 2. Stitch를 통한 AI 화면 생성

### 사용 방법

1. Stitch 접속 및 프로젝트 생성
2. 원하는 화면을 자연어로 설명 (프롬프트 입력)
3. AI가 화면 디자인 자동 생성
4. 생성된 결과물 검토 및 수정

### 프롬프트 작성 팁

- 구체적이고 명확하게 설명
- 원하는 레이아웃, 색상, 컴포넌트 명시
- 참고할 디자인 스타일 언급

## 3. Stitch에서 Figma로 가져오기

### Figma 플러그인 활용

1. Figma에서 Stitch 플러그인 설치
2. Stitch에서 생성한 디자인 선택
3. 플러그인을 통해 Figma로 import
4. Figma 내에서 추가 편집 가능

## 5. 공통 컴포넌트 분리

### 공통 컴포넌트란?

여러 화면에서 반복적으로 사용되는 UI 요소를 독립적인 컴포넌트로 분리한 것

### 분리 대상 예시

- **Header/Navigation**: 상단 네비게이션 바
- **Footer**: 하단 정보 영역
- **Button**: 다양한 스타일의 버튼
- **Input Field**: 입력 필드 컴포넌트
- **Card**: 정보 표시용 카드

### 분리하는 이유

1. **일관성 유지**: 동일한 디자인 요소가 모든 화면에서 동일하게 표시
2. **유지보수 용이**: 한 곳에서 수정하면 모든 곳에 반영
3. **개발 효율성**: 개발자가 재사용 가능한 컴포넌트로 구현 가능
4. **디자인 시스템 구축**: 체계적인 디자인 자산 관리

### Figma에서 컴포넌트 만들기

1. 공통 요소 선택
2. 우클릭 → "Create Component" 또는 `Ctrl + Alt + K`
3. 컴포넌트 이름 규칙에 맞게 명명
4. 필요시 Variants 추가 (버튼 상태, 크기 등)

## 6. 색상 테마 정리(실습코치님의 조언을 듣고 공부함)

### 색상 테마란?

프로젝트 전체에서 사용되는 색상 팔레트를 체계적으로 정의한 것

### 색상 분류

| 분류                      | 용도             | 예시                   |
| ------------------------- | ---------------- | ---------------------- |
| **Primary**               | 주요 브랜드 색상 | 메인 버튼, 강조 요소   |
| **Secondary**             | 보조 색상        | 서브 버튼, 부가 정보   |
| **Background**            | 배경 색상        | 페이지 배경, 카드 배경 |
| **Text**                  | 텍스트 색상      | 제목, 본문, 캡션       |
| **Border**                | 테두리 색상      | 입력 필드, 구분선      |
| **Success/Error/Warning** | 상태 색상        | 알림, 유효성 검사      |

### 색상 테마 정리의 이유

1. **브랜드 일관성**: 통일된 시각적 아이덴티티 유지
2. **개발 연동**: CSS 변수나 디자인 토큰으로 쉽게 변환
3. **다크 모드 지원**: Light/Dark 테마 전환 용이
4. **협업 효율**: 디자이너-개발자 간 명확한 색상 가이드

### Figma에서 색상 스타일 등록

1. 색상 선택 후 "Color Styles" 패널 열기
2. "+" 버튼으로 새 스타일 추가
3. 명명 규칙에 따라 이름 지정 (예: `Primary/500`, `Text/Body`)
4. 프로젝트 전체에서 일관되게 사용

## 7. 이러한 작업을 하는 이유

### 디자인 시스템의 중요성

| 이점          | 설명                                     |
| ------------- | ---------------------------------------- |
| **효율성**    | 반복 작업 감소, 빠른 화면 제작           |
| **일관성**    | 모든 화면에서 통일된 UX 제공             |
| **확장성**    | 새로운 화면 추가 시 기존 컴포넌트 재사용 |
| **협업**      | 팀원 간 명확한 디자인 언어 공유          |
| **개발 연동** | 디자인-개발 간 원활한 핸드오프           |

### 실무에서의 적용

- 스타트업부터 대기업까지 디자인 시스템 필수화
- Figma의 Design System 기능과 연계
- 개발팀의 컴포넌트 라이브러리와 1:1 매핑
