Redis 정리
1. Redis란 무엇인가

Redis(Remote Dictionary Server)는
메모리 기반(Key-Value) NoSQL 데이터 저장소로
초고속 읽기/쓰기가 필요한 시스템에서 주로 사용.

인메모리(In-Memory) 구조

네트워크 기반 데이터 저장소

단순 캐시를 넘어 다양한 자료구조 제공

2. Redis의 핵심 특징
   2.1 인메모리 기반

모든 데이터를 RAM에 저장

디스크 기반 DB 대비 매우 빠른 응답 속도

평균 응답 시간: sub-millisecond

장점

초고속 처리

실시간 시스템에 적합

단점

메모리 용량 제한

메모리 비용이 상대적으로 높음

2.2 다양한 자료구조 지원

Redis는 단순 Key-Value가 아닌 고급 자료구조를 제공.

자료구조	용도
String	캐시, 토큰
List	큐, 로그
Set	중복 제거, 태그
Sorted Set(ZSet)	랭킹, 우선순위
Hash	객체 저장
Bitmap	플래그 관리
HyperLogLog	유니크 카운트
Stream	메시지 스트림
2.3 단일 스레드 기반(Event Loop)

단일 스레드로 명령 처리

I/O 멀티플렉싱(epoll) 사용

특징

락(lock) 없음

예측 가능한 성능

CPU 연산이 무거운 작업에는 부적합

2.4 영속성(Persistence) 지원

메모리 기반이지만 데이터 보존 가능

방식	설명
RDB	특정 시점 스냅샷
AOF	모든 쓰기 명령 로그 기록
혼합	RDB + AOF

캐시뿐 아니라 세미 영속 저장소로도 사용 가능

2.5 TTL(Time To Live) 지원

키 단위로 자동 만료 시간 설정 가능

만료 시 자동 삭제

SET key value EX 60

2.6 원자적 연산(Atomic Operation)

모든 명령은 원자적

동시성 이슈 최소화

예시

INCR

DECR

ZINCRBY

3. Redis의 주요 특성 요약
   구분	특성
   성능	매우 빠름
   저장 방식	메모리 중심
   동시성	단일 스레드
   확장성	클러스터링 지원
   용도	캐시, 세션, 메시지, 랭킹
4. Redis 사용 예시
   4.1 캐시(Cache)

가장 대표적인 사용 사례

DB 조회 결과 캐싱

인기 게시글, 메인 페이지 데이터

Key: post:123
Value: 게시글 JSON
TTL: 300초


효과

DB 부하 감소

응답 속도 개선

4.2 세션 저장소(Session Store)

로그인 세션 관리

서버 무상태(stateless) 구성 가능

Key: session:userId
TTL: 30분

4.3 랭킹 시스템 (Sorted Set)
ZADD ranking 100 userA
ZADD ranking 200 userB


점수 기반 순위

실시간 조회 가능

활용 예

게임 랭킹

운동량 랭킹

조회수 순위

4.4 메시지 큐 / 이벤트 처리

List, Stream 활용

비동기 처리에 적합

LPUSH queue message
RPOP queue


활용 예

알림 처리

비동기 작업 큐

4.5 분산 락(Distributed Lock)
SET lock:key value NX PX 3000


활용 예

쿠폰 선착순 이벤트

중복 요청 방지

경매 입찰 제어

4.6 Rate Limiting (요청 제한)

IP 또는 사용자 기준 요청 횟수 제한

INCR request:userId
EXPIRE request:userId 60

4.7 실시간 통계 / 카운팅

조회수

좋아요 수

접속자 수

INCR view:postId
