## 답변 스크립트

<aside>
👉

링크드리스트는 각 요소가 노드 단위로 구성되고, 각 노드는 데이터와 다음 노드를 가리키는 포인터를 통해 연결되는 선형 자료구조입니다.

배열과 달리 메모리에 연속적으로 저장되지 않기 때문에 인덱스를 통한 직접 접근은 불가능하고, 탐색에는 O(n)의 시간이 걸립니다.

하지만 특정 위치의 노드를 알고 있는 경우에는 포인터 연결만 변경하면 되기 때문에 삽입과 삭제는 O(1)로 수행할 수 있습니다. 다만 노드 위치를 모르는 경우 노드 위치 탐색에 O(N)이 소요됩니다.

링크드 리스트에는 다음 노드만 참조하는 단일 연결 리스트와, 이전과 다음 노드를 모두 참조하는 이중 연결 리스트가 있습니다.

</aside>

> `주요 키워드`
> 
> - 노드, 데이터와 포인터
> - 비연속적 메모리, 인덱스 접근
> - 탐색 O(N), 삽입 / 삭제 O(1) (단 위치 파악에 어차피 O(N) 소요)
> - 단일 연결 리스트 / 이중 연결 리스트

## 질문의 의도

- 링크드 리스트의 기본 구조(노드, 포인터)를 이해하고 있는지
- 배열과의 차이 (꼬리 질문을 통해 파악하려는 의도)
- 삽입·삭제가 왜 O(1)이 되는 경우와 O(N)이 되는 경우 구분
- 탐색이 O(n) 이 되는 구조적 한계
- 어떤 상황에서 링크드 리스트가 적합하거나 부적합한지

요약 : 자료구조의 동작 원리 + 시간 복잡도 + 사용 시점 판단 능력을 함께 평가하는 질문

## 꼬리 질문

### 1. 일반 배열과 링크드리스트를 비교해 주세요.

- 답변 (스포방지)
    
    <aside>
    👉
    
    배열은 연속 메모리 기반으로 접근이 빠르고 캐시 효율이 좋은 반면, 링크드 리스트는 비연속 메모리 구조로 삽입과 삭제에 유리하지만 탐색 성능은 떨어집니다.
    
    </aside>
    
    - 핵심
        - 연속 vs 비연속 메모리 구조
        - 삽입 / 삭제 : 링크드리스트 우위
        - 탐색 : 배열 우위

### 2. 링크드리스트를 사용해서 구현할 수 있는 다른 자료구조에 대해 설명해주세요

- 답변 (스포방지)
    
    <aside>
    👉
    
    링크드 리스트를 사용해서 구현할 수 있는 자료구조로는 스택, 큐, 덱이 있습니다.
    
    스택은 링크드 리스트의 head를 top으로 사용해 LIFO 구조를 만들 수 있고,
    
    큐는 head에서 삭제하고 tail에서 삽입하는 방식으로 FIFO 구조를 구현할 수 있습니다.
    
    또한 이중 연결 리스트를 사용하면 head와 tail 양쪽에서 삽입과 삭제가 가능한 덱을 구현할 수 있습니다.
    
    이러한 자료구조들은 삽입과 삭제가 빈번한 경우 활용되기 때문에, 포인터 연결만 변경하면 되는 링크드 리스트가 적합합니다.
    
    </aside>
