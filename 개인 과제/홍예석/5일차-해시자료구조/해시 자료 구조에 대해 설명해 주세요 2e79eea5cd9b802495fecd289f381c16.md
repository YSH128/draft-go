## 답변 스크립트

(여기에 답변 작성)

<aside>
👉

해시는 키를 해시 함수로 변환해 배열 인덱스로 매핑함으로써 데이터를 평균 O(1)에 조회할 수 있는 자료구조입니다.

해시 함수로 계산된 인덱스를 통해 바로 접근하기 때문에 탐색이 빠르지만, 서로 다른 엔트리가 같은 인덱스로 매핑되는 충돌이 발생할 수 있습니다.

이 충돌은 체이닝이나 개방 주소법 같은 방식으로 해결하고, Java의 HashMap은 체이닝 방식을 사용합니다.

충돌이 많아질 경우 최악의 경우 O(n)까지 성능이 떨어질 수 있습니다.

다만 Java의 HashMap은 충돌이 심해질 경우 내부 구조를 트리로 변환해 최악의 성능을 완화합니다.

</aside>

> `주요 키워드`
> 
> - 키, 해시 함수, 값(데이터)
> - key : value를 합쳐서 entry라고 부름
> - 인덱스 접근
> - 체이닝
> - O(1), 충돌, O(N)

## 질문의 의도

- 해시의 핵심 아이디어(키 → 인덱스) 이해 여부
- 왜 탐색이 O(1) 이 가능한지
- 충돌(Collision)이 왜 발생하고 어떻게 해결하는지
- 평균 시간 복잡도와 최악의 경우(O(n)) 인식 여부
- Java HashMap 같은 실사용 자료구조에 대한 이해

## 간략 설명

- 핵심
    - 해시의 목표는 탐색을 평균 O(1)로 만드는 것.
    - 이를 위해 공간 복잡도를 희생하고 시간 복잡도를 개선는 자료 구조
    - 따라서 탐색 시간복잡도가 O(1)인 인덱스 즉시 접근이 가능하도록 배열 기반의 자료구조 활용
- Java의 HashMap에 기반한 Hash 자료 구조의 동작 원리
    - Key를 해시 함수를 통해 큰 정수로 변환
    - 큰 정수를 (capacity - 1)와 & 비트 연산하여 인덱스를 계산
        - capacity가 2의 제곱일 때, 배열 크기로 나눈 나머지와 같은 효과
    - 결과로 0 이상 capacity 미만의 값이 도출되어, 배열 인덱스로 안전하게 사용 가능
    - 인덱스 사이마다 값이 들어 있지 않은 인덱스가 존재할 수 있음 → 메모리 낭비
    - 하지만 메모리를 일부 희생하고 탐색 O(1)의 장점을 얻는 것.
- Java의 HashMap이 메모리를 스케일링하는 과정
    - HashMap의 기본 capacity는 16
    - HashMap의 기본 load factor(적재율)는 0.75
    - 데이터 수(N)가 16의 75%인 12를 초과하면 배열 크기를 2배로 늘리고,인덱스를 다시 계산해 평균 탐색 성능을 유지
    - 이러한 구조는 엔트리 수가 증가할수록 평균 버킷 길이가 길어져 탐색 비용이 증가하기 때문에, 이를 방지해 평균 O(1) 성능을 유지하기 위한 설계
- 해시 자료구조가 {“a” : 1} 을 저장하게 되는 과정

```bash
"a" (key)
 ↓
hashCode() → 97 (큰 정수)
 ↓
index 계산 → 97 % 16 = 1 (97 & 15 -> 1100001 & 1111 -> 0001 -> 1)
 ↓
table[1]에 저장
 ↓
충돌 시 LinkedList로 연결 (충돌이 심해지는 경우 트리 구조로 다시 변환)
 ↓
데이터 12개 초과
 ↓
capacity (배열의 크기) 32로 확장
 ↓
index 재계산 후 재배치
```

## 꼬리 질문

### 1. 값이 주어졌을 때, 어떻게 하면 충돌이 최대한 적은 해시 함수를 설계할 수 있을까요?

- 답변 (스포방지)
    
    <aside>
    👉
    
    충돌을 줄이기 위해서는 키의 패턴을 깨서 해시값이 버킷 전체에 균등 분포되도록 설계하는 것이 핵심입니다.
    
    또한 로드 팩터를 통해 데이터가 일정 수준 이상 적재되면 리사이징하여 평균 탐색 성능을 유지합니다.
    
    다만 리사이징과 리해싱에는 비용이 들기 때문에 성능과 메모리 사용 간의 트레이드오프를 고려해야 합니다.
    
    </aside>
    

### 2. 해시값이 충돌했을 때, 어떤 방식으로 처리할 수 있을까요?

- 답변 (스포방지)
    
    <aside>
    👉
    
    해시 충돌은 체이닝이나 개방 주소법으로 처리할 수 있습니다.
    
    체이닝은 같은 인덱스에 매핑된 데이터를 링크드 리스트로 연결하는 방식이고,
    
    개방 주소법은 충돌 시 다른 빈 버킷을 탐색해 저장하는 방식입니다.
    
    Java의 HashMap은 체이닝 방식을 사용하며, 충돌이 심해지면 트리 구조로 변환해 성능을 보완합니다.
    
    </aside>
    

### 3. 본인이 사용하는 언어에서는, 어떤 방식으로 해시 충돌을 처리하나요?

- 답변 (스포방지)
    
    <aside>
    👉
    
    자바의 HashMap에서는 체이닝 방식을 활용하여 충돌을 해결합니다.
